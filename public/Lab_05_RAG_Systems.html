Lab 05

RAG systems, neighbors, and evaluation

Production assistants rarely stop at “embed and search.” This lab surveys patterns that sit next to vanilla RAG: better retrieval, safer answers, and tooling that looks like agents.

Beyond flat vector search

  • Hybrid retrieval — combine keyword search (BM25) with dense vectors so rare tokens and paraphrases both surface good chunks.
  • Re-ranking — retrieve a wide candidate set (e.g. 50), then score pairs (query, chunk) with a cross-encoder for sharper ordering.
  • Query rewriting — expand or decompose the user question (multi-query) to improve recall on ambiguous prompts.
  • Metadata filters — restrict search by tenant, product, date, or ACLs before similarity runs.

Grounding, citations, and trust

For regulated or high-stakes answers, teams often require inline citations to retrieved spans. That means storing stable chunk IDs, page offsets, or URLs and asking the model to quote them—then validating that cited text actually appears in the retrieved set (post-checks or constrained decoding).

Agents vs. RAG

RAG is usually one retrieve-then-read pass (maybe with rerank). Agents loop: plan → call tools (search, SQL, calculators) → observe → repeat. Tool-using agents can implement RAG as one tool among many; the hard parts become orchestration, budgets, and auditing every tool call.

Evaluation (what to measure)

  • Retrieval quality — is the gold passage in the top‑k? (hit rate, MRR, nDCG)
  • Answer faithfulness — does the answer contradict the provided context? (LLM-as-judge or entailment models)
  • Latency & cost — embedding calls, rerankers, and context length drive price per query.
  • Freshness — time from document update to searchable index.

Sketch: minimal RAG orchestration

# Pseudocode — not executed in this static lab
chunks = chunk_documents(docs)
index = VectorIndex(embed(chunks))

def answer(question):
    q = embed(question)
    ctx = retrieve(index, q, k=8)
    prompt = build_prompt(ctx, question)
    return llm.generate(prompt)

Swap llm.generate for the browser inference path in this repo when experimenting with small models; plug in your favorite vector store for retrieve.

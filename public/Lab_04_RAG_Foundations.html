Lab 04

Retrieval-augmented generation (RAG): foundations

Large language models only “know” what was in their training data. RAG connects a model to your documents at query time by retrieving relevant passages and injecting them into the prompt.

Why RAG exists

Static weights go stale the day after training. Fine-tuning on every document update is expensive. RAG instead keeps a mutable document store and lets the model read excerpts on demand—similar in spirit to letting a human analyst open the right file before answering.

The core pipeline

Documents └── chunk (split into overlapping segments) └── embed (vector per chunk) └── index (vector DB or ANN library) User question └── embed query vector └── retrieve top‑k similar chunks └── augment prompt (context + question) └── LLM generates answer
  • Chunking — split text into pieces small enough to fit context windows; overlap reduces boundary cuts through sentences.
  • Embeddings — map text to dense vectors so “similar meaning” is near in vector space.
  • Retriever — approximate nearest neighbors (ANN) over millions of vectors in milliseconds.
  • Augmentation — prepend retrieved chunks with instructions (“Answer using only the following context…”).

Failure modes you should expect

  • Wrong chunks — the retriever misses the passage that contains the answer (recall problem).
  • Lost in the middle — models sometimes underweight evidence buried in very long contexts.
  • Hallucination with citations — the model may still confabulate unless you enforce grounding rules.
  • Stale index — documents change; embeddings must be refreshed or versioned.

Mini glossary

  • Vector store — database specialized for similarity search over embeddings.
  • Top‑k — retrieve the k closest chunk vectors to the query vector.
  • Cosine similarity — common score between two unit-normalized embedding vectors.
  • Token budget — hard limit on how much retrieved text fits beside the user question.

Where this repo connects

This project trains a small GPT-style decoder and runs inference in the browser—the same family of models often used as the “generator” step in RAG. The retrieval side (chunking, embedding APIs, vector DB) is not bundled here; Lab 05 sketches how you would wire them in production.
